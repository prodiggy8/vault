Given array $a_{0}, \dots, a_{n}$ and an interval $[i, j)$, we want to answer queries about $a_i, \dots, a_{j-1}$.

For a sum query, we can just sum all elements in $\Theta(j=i) \in O(n)$. We can also do prefix sums which takes $O(n)$ preprocessing and $O(1)$ for multiple queries, but this doesn’t allow for modifications.

Idea: we create a tree of intervals of variable size (e.g., leaves one element, root all of them). We prove not many intervals are needed to represent any interval as a sum of intervals.

Suppose we use three adjacent blocks on the same level, each half the size of its parent and hence two could be substituted by the parent.

Now suppose three non adjacent ones. It must be the case the leftmost of these is a right child otherwise we could just substitute it with its parent in the contiguous block. Conversely, the rightmost block is a left child. Hence the one in the middle could be instead covered by some intervals between the leftmost and the rightmost interval.

Applying this argument up the tree there is a construction with at most two blocks per level because blocks of three don’t generate the minimum number of blocks.

**Hence:** any interval $[i, j)$ can be made up of a set of at most $2\log n$ disjoint blocks from the tree.

### Segment Tree

**Binary heap indexing trick:** Given $T[1..N]$, place the root at position 0, given node $i$, place its left child in $2i+1$ and right child in $2i + 2$.

> [!definition] Segment Tree
> $\operatorname{Parent}(i)=\left\lfloor  \frac{i-1}{2}  \right\rfloor$
> $\operatorname{LeftChild}(i)=2i + 1$
> $\operatorname{RightChild}(i)= 2i + 2$
> 
> **Construction:** We copy $A[0..n-1]$ into last $n$ elements, the leaves. Iterate over all notes to fill them up going from end to beginning of the array.
> 
> **Updating:** Update element at position $i$ and go up the tree until we reach $0$ in $O(\log n)$ time.
> 
> **Querying:** We do a divide and conquer sum, but we only do that when the current level has an interval that contains elements from $[i,j)$ and elements not from $[i,j)$. This is $O(\log n)$.

```pseudo
Sum(u, i, j):
	node = nodes[i]
	
	if [i, j] is this exact interval:
		return node
	else:
		if i is contained in the right child:
			return sum(RightChild(u), i, j)
		if j is contained in the left child:
			return sum(LeftChild(i), i, j)
		else
			return sum(LeftChild(u), i, mid)
				+ sum(RightChild(u), mid, j)

RangeSum(i, j):
	return sum(0, i, j)
```

#### Inversion Count

Given permutation $p$ from $0$ through $n-1$ the number of inversions is the number of pairs $i$, $j$, such that $i < j$ but $p[i] > p[j]$.

We can loop through all $j$ and $i < j$ in $O(n^2)$. With segment trees, we need a range corresponding to the count of the number of elements we’ve seen greater than a certain value.

We create a tree with all zeros. To count elements greater than $p[j]$ we can use $\operatorname{RangeSum(p[j], n)}$ and we assign a $p[j]=1$ (meaning we’ve seen it) in the node after such. Total cost is $O(n \log n)$.

#### Extending segment trees

We can implement **any associative operation**, not only addition, using segment trees. Examples: minimum and maximum.

We can add instead of assigning: $\operatorname{Add}(i, x)=\operatorname{Assign}(i, x + \operatorname{RangeSum}(i, i + 1))$
