#### Time standards
- Greenwich Mean Time: based on astronomical observations
- International Atomic Time: based on Cesium atom radiation cycles; started 1958
- UTC: atomic + leap seconds (currently 27) to be within 0.9s of Greenwich
	- Broadcast from radio stations on land and satellite (e.g. GPS).

**Drift:** difference per unit of time from some ideal reference clock.

# Synchronization 

Network with propagation delay of exactly $d$.
1. Sender sends time $T$
2. Receiver sets clock to $T+d$

Now one with propagation delay *at most* $D$
1. Sender sends time $T$
2. Receiver sets to $T+\frac{D}{2}$
3. Error is at most $\frac{D}{2}$

## Cristian’s synchronization algorithm
- Client requests for time
- Client set’s clock to $T+\frac{RTT}{2}$ where $RTT$ is round trip time

##### Calculating error

We don’t know exactly how much each leg took. Let $m$ be the minimum time it takes due to physical constraints for the message to arrive.

The earliest the reading could be is if the request took as long as possible and the response took as little as possible, so $T+m$.

The latest would be if the request was $m$ and the reply took all the rest of $RTT$.

Hence we get bounds $\left[T+m, T+RTT-m\right]$.

Let $a$ is request delay and $b$ is response delay with $a,b\geq min,\; a+b=\text{RTT}$
$$
\begin{align}
e&=\left( T-\frac{\text{RTT}}{2} \right)-(T+b)=\frac{\text{RTT}}{2}-b \\
b &\geq \min \\
b &\leq \text{RTT} - \min \\
b &= \min \implies e=\frac{\text{RTT}}{2}-\min \\
b &= \text{RTT}-\min\implies e=-\left( \frac{\text{RTT}}{2} - \min\right)
\end{align}
$$

## Berkeley algorithm

Clock synchronization for a group of computers, master-slave architecture.
1. Time daemon asks all about their clocks
2. Uses round trip time to estimate the workers’ clocks
3. Computes average, tells all how to adjust their clock (in terms of increments or decrements)

# Lamport clock

Time doesn’t matter, just the order of the events. Rules:
1. If a, b happened in process p, trust p for the order
2. If message is sent between two processes, send happens before receive
3. Transitivity

![[lamport.png]]

Not all events are related. a and e here are said to be **concurrent**, written $a || e$.

Processes can keep logical clocks $L$ not related to physical ones.
1. $L_{i}$ is incremented before each event
2. When process $p_{i}$ sends message, sends also logical time $t=L$
3. When process $p_{i}$ receives message $(m,t)$, sets $L_{j}=\max(L_{j}, t) + 1$

> [!Theorem]
> $$e \rightarrow e' \implies L(e) < L(e')$$
> But $L(e) < L(e') \not\implies e \rightarrow e'$. As an example, an event can be concurrent to another but their times might be related, such as $b$ and $e$ in the picture above.

What if we need a total order? Use Lamport’s algorithm, but break ties using process ID

# Vector clock

They overcome a shortcoming of Lamport clocks:  $L(e) < L(e') \not\implies e \rightarrow e'$.

**How?**
- Label each event by vector $V(e)[c_{1}, c_{2}, \dots, c_{n}]$
- $c_{i}=$ # events in process $i$ that causally precede $e$

1. Initialize all zero vectors
2. For event on process $i$, increment own $c_i$
3. Label message sent with local vector
4. When process $j$ receives the message with vector $[d_{1}, \dots, d_{n}]$
	- Set each local entry $k$ to $\max(c_{k}, d_{k})$
	- Increment $c_j$

Each event has a vector associated with them. To do comparisons like $<$, $\leq$, and $\max$ we just compare the vectors component wise.
- $V=W$ iff $V[i]=W[i] \forall i$
- $V \leq W$ iff $V[i] \leq W[i] \forall i$
- $V || W$ iff neither $V \leq W$ or $W \leq V$, i.e., some components are bigger in $V$ while some are bigger in $W$.

Here: $e \rightarrow e' \implies V(e) < V(e')$ and the converse is **also true**.
